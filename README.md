## Завдання

### Завдання 1: Базова реалізація (без debounce)
* Реалізувати GPIO interrupt на `FALLING`.
* При кожному interrupt:
    * інкрементувати лічильник;
    * виводити лічильник у лог.
* **Очікуваний результат:** 1 фізичне натискання викликає кілька interrupt. Переривання викликається і при відпусканні кнопки.

### Завдання 2: Software debounce через таймер (time-based)
* Додати debounce на основі часу: ігнорувати interrupt, якщо з моменту попереднього пройшло < 50 мс.
* Реалізувати логіку поза ISR.
* **Очікуваний результат:** Менше хибних спрацювань. Все ще можливі спрацювання при відпусканні кнопки.

### Завдання 3: Debounce через перевірку рівня (state-based)
* Interrupt лише сигналізує про "подію".
* У `loop()` / `task`:
    * приймати подію, лише якщо кнопка досі натиснута;
    * ігнорувати події при відпусканні.
* **Очікуваний результат:** Рівно 1 реакція на 1 натискання. Release не викликає жодної дії.

### Завдання 4: Polling + debounce (без interrupts)
* Прибрати interrupt повністю.
* Опитувати кнопку кожні 5–10 мс.
* Реалізувати debounce як машину станів (кінцевий автомат).
* **Очікуваний результат:** Найстабільніша поведінка серед програмних методів. Присутня трохи більша затримка реакції.

### Завдання 5: Hardware debounce

* Додати RC-фільтр (конденсатор 100nF і резистор 100Ω, підтягуючий резистор незмінний — 10kΩ).
* Повторити частини 1-4 з підключеним фільтром.
* Порівняти результати з RC-фільтром та без нього.
